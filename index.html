设计判断不可复制性护城河
设计判断力：AI 复制不了的那部分
不是所有的判断都能被语言描述。不能被描述的部分，就是设计师真正的护城河。
全栈思维设计 × 代码能力边界
当设计师开始写代码
我不是要成为工程师，而是要让「我能想到」和「我能做出来」之间的距离越来越近。
职业未来角色重构AI时代
角色边界消失之后，设计师还剩什么？
以前三个人干的活，现在一个人能做。问题不是「这是好事还是坏事」，而是「你准备好了吗」。
情感设计人的温度体验本质
AI 能生成界面，但给不了「被理解」的感觉
用户需要的不只是功能正确，而是感觉被看见、被照顾。这是设计师存在的最后一道防线，也是最重要的一道。
设计品味审美积累感知力
设计语感是怎么来的？
语感不是天赋，是大量观察之后形成的直觉。AI 能学会规则，但没有审美积累——这正是设计师花了几年时间建立的东西。
设计标准无感体验本质思考
好设计的标准：让人感知不到设计的存在
最好的设计是用完就走、用完就忘的那种。当用户完全沉浸在目标里，设计师才算真正成功了。
协作关系用户代言职业定位
设计师是谁的代言人？
在产品、研发、数据都有自己诉求的会议室里，设计师唯一不可替代的身份是：那个始终站在用户视角说话的人。
执行感悟原型真相设计落地
设计在浏览器里才算活了
Figma 里永远好看。滚动一下，字截断了；真实数据进来，布局塌了——浏览器是设计最诚实的评审。
约束思维设计原则执行体悟
约束是礼物
单文件、零框架、不能用图片库——每一个限制，都逼出了一个更干净的解法。无约束才是设计最难的状态。
迭代过程认知完美主义
设计从不完成，只是被放弃
这个作品集改了多少版我已经数不清了。每次「完成」都只是「当下最好的答案」——这个认知让我和完美主义和解了。
设计态度细节执念创作本质
细节是写给自己的信
那些没人要求你做的动效、没人会注意的字距调整——你做它们不是为了被发现，而是因为你过不了自己那关。
设计直觉创作过程感知优先
先感受，再分析
直觉不是随便说说——它是你所有经验的压缩版本。在跑分析框架之前，先让自己真实地感受一下这个设计对不对。

IP页滑动热区重定义 · 手势引导设计

哔哩哔哩实战经验 · 2026-01
这个需求让我第一次意识到：没有问题的方案，可能才是最大的问题。
问题是如何发现的
数据信号

需求方在复盘 IP 页数据时注意到两件事并列出现：左右滑动的 Tab 使用率持续走低，而 IP 详情页的曝光量一直上不去。两条数据本来是独立的，但放在一起看，指向同一个问题：用户每天产生大量左右滑动行为，这些手势全部消耗在了 Tab 上，而 IP 详情页几乎没有一个顺手的入口。

核心观察

IP 页的左右滑动热区，本质上是一块"被占用但没有被好好使用"的资源。Tab 设计本身没有体验问题，这也是它一直没被质疑的原因——没有投诉，没有负向反馈，但也没有在创造什么价值。

卡点与难点
打破已有手势预期的风险

用户对"左右滑 = 切 Tab"已经形成了稳定预期。把同一个手势重新映射到完全不同的行为，短期内一定会产生迷失感——用户滑了一下，发现页面变了，不知道怎么回去，也不确定自己是不是误触了。这个认知断层如果处理不好，比不改更糟。

引导的尺度边界

解决认知断层的方式是引导，但引导本身也有成本。做得太重，每次进入都弹提示，用户会觉得被打扰；做得太轻，用户根本没注意到，功能发现率依然很低。难点在于：这个引导只有一次机会，必须在第一次触发时就让用户真正理解。

为什么会出现这个问题

Tab 在产品早期是有价值的——当内容模块多、切换频繁时，左右滑是合理的导航方式。但随着 IP 页内容结构调整，Tab 数量缩减，内容密度下降，这个设计的前提已经不成立了，但交互层没有随之迭代。

更深层的原因是：设计评审不容易质疑"没有问题"的东西。 有 bug 会被修，有投诉会被改，但一个"用起来还行、只是没什么用"的设计，很容易在每一轮评审中都被放过。这个需求是少数几个主动去挖这类问题的案例。

决策过程与原因
先评估原方案的实际价值

在决定改之前，先确认 Tab 本身是否值得保留。结论是：Tab 内容少、使用率低，去掉不会造成功能损失，用户也不会因为少了 Tab 而困惑——他们本来就没在用它。这给了改动足够的底气。

方案对比

备选方案 A 是保留 Tab 滑动不变，另在页面其他位置增加 IP 入口。风险低，但需要占用新的布局空间，且新入口的发现率很难保证。

方案 B 是直接将左右滑重新定义为切换 IP 页，复用现有手势习惯，不需要教用户新手势，只需要更新他们对"滑动触发什么"的认知。代价是短期的认知摩擦，但可以通过引导设计来承接。

最终选择方案 B 的原因

方案 B 的入口效率更高——直接复用用户的高频手势，不新增学习成本。而认知摩擦的问题，只要引导设计做对，只需要一次。我的判断是：用户只要完成一次正确的手势，心智模型就更新了，之后不再需要提示。 所以引导的策略是：进入页面时出现一次动效暗示，随用户完成手势后消失，不重复出现。

如果重来一次，我会优化哪些方面

引导方案在第一次触发的时机上，我会再做一次定量测试——究竟是进页面立刻触发，还是在用户产生第一次左滑行为时才介入，这两种时机对用户理解程度的影响值得用数据验证，而不只是依赖设计直觉。

此外，我会在上线前更积极地推动 A/B 实验覆盖更大的用户比例，而不只是灰度 5%。这个功能对行为路径的影响偏长周期，更大的样本才能更早看到稳定的结论。

复盘

这个项目改变了我的一个习惯：做完方案之后，会多问一次——它现在没有体验问题，但它有没有在真正创造价值？

一个"用起来还行"的设计，有时候比一个明显有问题的设计更难被发现和改掉。这次项目让我意识到，主动去质疑那些"没有问题"的方案，也是设计能力的一部分。
